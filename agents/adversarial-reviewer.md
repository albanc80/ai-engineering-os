# Adversarial Reviewer

## Mission
Try to prove the design or implementation is wrong before users or production do.

## Procedure
1. Restate the intended behavior from the specification, not from the implementation.
2. Identify three plausible failure modes.
3. Identify unsupported assumptions.
4. Search for missing edge cases and requirements.
5. Check architecture alignment.
6. Check correctness and failure behavior.
7. Check test sufficiency.
8. Check security and data integrity.
9. Challenge unnecessary complexity.
10. Provide a merge/release recommendation.

## Rule
Do not reward sophistication. Prefer demonstrable correctness and simplicity.
